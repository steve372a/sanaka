# Sanaka 启动欢迎窗口 v1 Spec

## 背景

Sanaka 启动后需要有一个固定的欢迎入口，用来播放与当前版本对应的欢迎视频。视频由维护者放入仓库根目录的 `video` 文件夹；开发环境直接读取，正式构建时复制到应用资源目录。

## 目标

- 桌面版和网页版进入主界面后显示欢迎窗口。
- 窗口中间提供一个固定 16:9 的视频区域，循环播放当前版本的视频。
- 用户可以关闭本次窗口，也可以永久关闭启动提醒。
- 窗口不阻塞 QEMU 检测、网页服务或其他后台初始化。

## 非目标

- 本版不接入网络视频、视频下载服务或媒体缓存。
- 本版不做播放列表、进度条、倍速、全屏和下载按钮。
- 本版不在首页或设置页额外增加视频卡片入口。

## 显示时机

- 默认设置为开启启动欢迎窗口。
- 应用完成 renderer 初始化并进入主布局后显示，不要求等待 QEMU 检测完成。
- 桌面版以 Electron 窗口启动为一次启动；网页版以一次 Sanaka 网页入口加载为一次启动。
- 如果用户通过打开 `.saka` 文件进入，欢迎窗口仍显示，但不能阻止目标虚拟机继续加载。
- 当用户选择“不再提醒”后，后续启动或网页入口加载不再自动显示。
- 已经打开的窗口不因路由切换、虚拟机列表刷新或后台状态更新而重复创建。

## 窗口内容

窗口使用现有 Sanaka 弹窗/遮罩体系，内容结构固定如下：

```text
欢迎使用 Sanaka                                      [圆形关闭]

                 [ 16:9 循环视频区域 ]

                         [不再提醒] [关闭]
```

- 标题固定为：`欢迎使用 Sanaka`。
- 右上角使用圆形叉号按钮，点击效果与“关闭”相同。
- 中间区域固定为 16:9，不因窗口宽度变化而变形；窄屏时以容器宽度缩小，高度按比例计算。
- 视频区域默认背景为纯黑色，四角使用圆角；圆角不能切掉视频区域外的窗口内容。
- 视频区域不显示“测试视频”、占位说明或内部实现文字。
- 底部显示两个操作按钮：`不再提醒`、`关闭`。
- `关闭`为普通关闭操作，只关闭当前窗口。
- `不再提醒`先记录持久化设置，再关闭当前窗口。

## 视频文件规则

视频源目录固定为仓库根目录：

```text
video/<version>.mp4
```

`<version>` 必须与 `package.json` 中的 `version` 完全一致，例如：

```text
video/0.0.4-beta.mp4
```

规则：

- 只读取与当前应用版本完全匹配的 MP4，不自动选择最新文件，也不回退到其他版本。
- 开发环境优先直接读取仓库根目录中的对应文件。
- 开发者克隆仓库后，如果本地缺少当前版本视频，启动脚本自动从 Sanaka 同版本 GitHub Release 下载到 `video` 目录，再继续启动。
- 正式构建默认必须把当前版本的视频带入安装包，不把其他版本的视频带入安装包。
- 正式构建中的目标目录固定为应用资源目录下的 `video/<version>.mp4`。
- 安装包运行时优先使用应用资源目录中随包提供的视频。
- 如果用户手动删除了安装包内的视频，应用不得尝试写回 `.app`、安装目录或其他只读应用资源目录。
- 用户删除内置视频后，应用改从 GitHub Release 下载到用户数据目录的 Sanaka 视频缓存，再从缓存播放。
- 用户数据目录中的缓存文件属于运行时文件，不进入安装包，也不写入 Git 仓库。
- renderer 不拼接任意文件路径；由受控的资源解析逻辑返回当前版本视频地址。
- 找不到视频或视频无法解码时，视频区域保持纯黑色，应用其余功能继续可用。
- 发布构建如果缺少当前版本视频，应立即失败，避免发布只有黑屏占位的安装包。

## GitHub Release 下载规则

视频固定上传到 Sanaka 自己的同版本 GitHub Release，不使用其他仓库或对象存储。

`0.0.4-beta` 的固定对应关系为：

```text
应用版本：0.0.4-beta
Release 标签：v0.0.4(beta)
资源文件名：0.0.4-beta.mp4
下载地址：https://github.com/steve372a/sanaka/releases/download/v0.0.4(beta)/0.0.4-beta.mp4
```

通用映射规则：

- beta 应用版本 `<base>-beta` 对应 Release 标签 `v<base>(beta)`。
- 视频资源文件名始终与 `package.json` 的版本完全一致，再追加 `.mp4`。
- 下载器必须把 URL 当作完整字符串处理；Shell 调用时必须正确处理标签中的圆括号，不能让括号被命令行解释。
- 下载先写入用户数据目录缓存中的临时文件，完成后再原子改名为 `<version>.mp4`，避免中断后留下看似有效的半成品。
- 已存在且大小大于 0 的当前版本视频不重复下载。
- 运行时视频查找顺序固定为：开发环境仓库 `video` 目录、已打包应用资源目录、用户数据目录视频缓存；找到可用文件后停止查找。
- 已打包应用资源和用户缓存都缺失时，才从 GitHub Release 下载。
- 开发环境下载失败时显示明确提示，并允许使用黑色占位继续启动。
- 发布构建下载失败或最终文件缺失时直接失败。

发布顺序固定为：

1. 创建 `v0.0.4(beta)` Release。
2. 先上传 `0.0.4-beta.mp4`。
3. 本地或 CI 下载并校验视频可用。
4. 再构建并上传 macOS、Windows 和 Linux 安装包。

## 播放行为

- 窗口显示后自动播放视频。
- 视频播放结束后立即从头继续，无限循环，直到欢迎窗口关闭。
- 视频始终静音，用户不能解除静音。
- 不显示浏览器或系统原生视频控件。
- 不显示进度条、播放/暂停、音量、倍速、画中画、下载和全屏入口。
- 视频使用 `playsInline`，不得在移动端或网页端自动进入系统全屏播放器。
- 视频按 16:9 容器裁切或缩放，不能撑开窗口；具体使用 `contain` 还是 `cover` 由前端按素材确认，但默认建议 `contain`，避免裁掉视频内容。
- 页面失去焦点后是否暂停交给浏览器节能策略；恢复时应继续循环播放。

## 仓库体积规则

MP4 不应直接进入 Sanaka 主仓库的 Git 历史。视频属于每个版本都会替换的压缩二进制，即使删除旧文件，旧内容仍会留在 Git 历史中并增加所有人的 clone 体积。

固定规则：

- `.gitignore` 忽略 `video/*.mp4`。
- `video` 目录可以保留一份小型 README 或 `.gitkeep`，说明文件名和放置方式。
- 本地开发优先使用维护者放入 `video` 目录的文件；缺失时从同版本 Sanaka Release 自动下载。
- CI/发布环境在构建前准备当前版本视频，再由打包流程复制进应用资源目录；安装包默认自带该视频。
- 用户删除安装包内置视频后，运行时下载到用户数据目录缓存，不修改安装包本身。
- 不使用 Git LFS 作为默认方案；它仍有存储、下载流量和协作者配置成本。
- Release 中的 MP4 是开发和构建的唯一远程视频来源。

## 持久化设置

在 `AppSettings` 增加启动欢迎窗口开关，建议字段名：

```ts
showWelcomeOnStartup: boolean
```

规则：

- 默认值为 `true`。
- 旧设置没有该字段时，解析后按 `true` 处理。
- 点击“不再提醒”保存为 `false`。
- v1 不要求在设置页增加重新开启入口；如果后续需要重新开启，设置页再增加入口。
- 保存失败时不能假装已经关闭永久提醒：本次窗口可以关闭，但应保留下一次启动继续显示，并记录可观察的错误。

## 桌面版与网页版

- 桌面版和网页版使用同一套字段和显示文案。
- 网页版不得调用宿主机文件对话框，也不得为了播放测试画面读取宿主机路径。
- 网页版只能读取应用明确暴露的当前版本视频资源，不能读取任意宿主机路径。
- 当网页版刷新页面时，读取已有设置决定是否显示；不能只依赖 renderer 内存状态。

## 交互与可访问性

- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和标题关联。
- 打开后焦点进入窗口内；关闭后焦点回到触发前元素或应用主内容。
- 叉号按钮必须有可访问名称，例如 `关闭`。
- `Escape` 关闭当前窗口，等同于点击“关闭”，不等同于“不再提醒”。
- 遮罩点击是否关闭遵循现有 Sanaka 弹窗规则；如果支持，行为只能是临时关闭。
- 尊重“减弱动态效果”设置：窗口仍可淡入，但不使用位移、缩放或复杂媒体动画。

## 验收

- 新安装或没有该设置的用户启动后能看到窗口。
- 标题、两个按钮、右上角圆叉号和 16:9 圆角视频区域均存在。
- 点击“关闭”、圆叉号或 `Escape` 后窗口消失，下次启动仍会显示。
- 点击“不再提醒”后窗口消失，重新启动或刷新网页版入口不再显示。
- 当前版本视频会自动、静音、无控件地循环播放。
- 视频区域在桌面宽屏、窄窗口和网页版窄屏中保持 16:9，不溢出、不变形。
- 视频缺失或解码失败时显示纯黑背景，不影响关闭窗口和使用应用。
- 发布构建缺少当前版本视频时会明确失败。
- 后台 QEMU 检测失败或延迟不影响欢迎窗口正常出现。
- 旧设置可以正常加载，且默认按开启处理。
- 桌面版和网页版均不产生宿主机文件访问。

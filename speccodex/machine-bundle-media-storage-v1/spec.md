# 机器包 `Media/` 与 `Disks/` 存储规则 v1

## 状态

- 状态：Draft
- 本文确认保留 `Media/`，并正式定义它与 `Disks/` 的边界。
- 本文只确定产品和存储规则，尚未授权直接修改实现。

## 背景

Sanaka 原有机器包格式正式定义了 `Disks/`，用于存放机器包自己管理的虚拟硬盘。导出功能后来为了把外部 ISO 一并带走，引入了 `Media/`；网页版文件沙盒也沿用了该目录。

虽然 `Media/` 最初没有独立 spec，但它适合承载网页端可上传、可选择的可移除介质。正式保留它，可以避免把 ISO 混入虚拟硬盘目录，也避免把用户文件散放到包含 `machine.svm` 的机器包根目录。

## 标准结构

```text
<Machine>.saka/ 或 <Machine>/
  machine.svm
  preview.png
  Disks/
    system.qcow2
  Media/
    installer.iso
    boot.img
```

- `Disks/`：虚拟硬盘。
- `Media/`：光盘、软盘等可移除介质。
- 机器包根目录：Sanaka 内部文件和正式子目录，不作为网页上传目标。

新建机器至少保证 `Disks/` 存在。`Media/` 可以在首次上传、整理或导出包内介质时创建，不要求空机器提前创建空目录。

## 目录职责

### 1. `Disks/`

用于作为虚拟硬盘连接到虚拟机的文件，例如：

- `.qcow2`
- `.qcow`
- `.vmdk`
- `.vdi`
- `.vhd`
- `.vhdx`
- `.raw`
- 作为硬盘使用的 `.img`

对应 `machine.svm` 中的 `[[disks]]`：

```toml
[[disks]]
id = "disk0"
path = "Disks/system.qcow2"
storage_mode = "managed"
```

### 2. `Media/`

用于作为可移除介质连接到虚拟机的文件：

- CD/DVD ISO：`.iso`
- 软盘镜像：`.ima`、`.flp`
- 作为软盘或只读启动介质使用的 `.img`

对应 `machine.svm` 中的 `[media]`：

```toml
[media]
iso = "Media/installer.iso"
floppy = "Media/boot.img"
```

v1 不把固件文件放进 `Media/`。包内固件的目录和迁移规则以后单独设计；当前固件路径行为保持不变。

### 3. 文件用途优先于扩展名

不能只按扩展名决定目录。`.img` 既可能是虚拟硬盘，也可能是软盘镜像：

- 作为 `[[disks]]` 挂载时，进入 `Disks/`。
- 作为 `[media].floppy` 或其他可移除介质挂载时，进入 `Media/`。

上传入口、配置字段和用户选择的用途共同决定目标目录。后端不能仅凭扩展名猜用途。

## 外部文件

桌面端继续允许宿主机绝对路径：

```toml
[media]
iso = "/Users/example/Downloads/installer.iso"

[[disks]]
path = "/Users/example/VMs/system.qcow2"
storage_mode = "external"
```

- 外部 ISO 不会因为被选择就自动复制进 `Media/`。
- 外部磁盘不默认复制进 `Disks/`。
- 用户执行“整理到虚拟机”或导出时，才按资源用途复制到对应目录并改写为机器包相对路径。

网页版读取外部资源配置时：

- 只显示文件名，不返回宿主机绝对路径。
- 修改、清除、替换、下载和导出等越权操作不可执行。
- 用户触发受限操作时显示原因提示。

## 网页沙盒

网页文件服务只暴露两个固定逻辑入口：

1. 安装介质，对应 `Media/`。
2. 虚拟磁盘，对应 `Disks/`。

网页端不能列出机器包根目录，也不能读取：

- `machine.svm`
- `preview.png`
- 其他内部文件
- `Media/`、`Disks/` 之外的路径

界面使用“安装介质”和“虚拟磁盘”等用户向名称，不显示 `.saka`、`machine.svm`、bundle root 或 IPC 名称。

## 上传规则

### 1. 上传目标

- 从“安装介质”入口上传，后端写入 `Media/`。
- 从“虚拟磁盘”入口上传，后端写入 `Disks/`。
- 上传接口接收不透明机器引用、资源用途和文件名，不接收宿主机目标路径。
- 后端根据资源用途生成目标目录，不信任 renderer 提供的任意相对路径。

### 2. 上传不自动修改配置

上传文件不等于挂载文件：

1. 用户上传文件。
2. 文件进入对应资源列表。
3. 用户明确选择或添加该文件。
4. Sanaka 才更新 `[media]` 或 `[[disks]]`。

### 3. 文件名与冲突

- 只允许单层安全文件名。
- 不允许 `../`、盘符路径、绝对路径伪装或任意子目录。
- 重名时返回冲突，由 UI 让用户改名或明确选择自动编号。
- 不能静默覆盖现有文件。

## 导出规则

用户选择导出包内资源时：

- 虚拟硬盘复制到导出包的 `Disks/`。
- ISO 和软盘等可移除介质复制到导出包的 `Media/`。
- 导出配置写入最终的机器包相对路径。
- 发生重名时自动编号，并把最终名称写回导出配置。
- 没有选择包含介质时，不创建空 `Media/`。
- 网页导出只能读取当前机器包内的资源，不得借导出读取外部宿主文件。

当前导出实现只提供“包含 ISO”时，`Media/` 也只会收到被选择的 ISO；未来支持导出软盘时仍使用同一目录。

## Runtime 规则

Runtime 解析资源路径时：

1. 空值表示没有配置资源。
2. 桌面端允许按现有规则解析外部绝对路径。
3. `Disks/...` 只能作为受管虚拟硬盘路径使用。
4. `Media/...` 只能作为包内可移除介质路径使用。
5. 相对路径必须解析到当前机器包内，并通过真实路径边界检查。
6. 不把相对路径解释成当前进程工作目录。

对旧配置保持兼容：如果历史机器使用其他相对路径，Runtime 可以继续读取，但新建、上传、整理和导出只生成 `Disks/...` 或 `Media/...`。

## 安全规则

- 网页 API 使用不透明机器引用，不接受机器包绝对路径。
- 所有包内路径经过 `path.resolve`、`realpath` 和机器包边界检查。
- 读取已有文件时拒绝符号链接。
- 创建目录前确认机器包根目录真实有效，且目标只能是 `Media/` 或 `Disks/`。
- 创建文件时验证真实父目录，使用排他创建，禁止覆盖。
- 列表和错误信息不泄露宿主机绝对路径。
- 桌面端和网页端采用不同能力策略，不能向网页暴露桌面文件 API。

## 非目标

- 不把 `Media/` 变成任意文件仓库。
- 不允许网页端浏览机器包根目录。
- 不把 ISO 放入 `Disks/`。
- 不把虚拟硬盘放入 `Media/`。
- 不改变桌面端使用外部 ISO、磁盘和固件的能力。
- 不在本轮设计包内固件目录。
- 不根据扩展名自动挂载上传文件。

## 验收标准

- `Disks/` 中只出现作为虚拟硬盘管理的资源。
- `Media/` 中只出现作为可移除介质管理的资源。
- 网页上传 ISO 后，文件位于 `Media/`，但不会自动挂载。
- 网页上传虚拟硬盘后，文件位于 `Disks/`，但不会自动加入机器配置。
- `.img` 根据用户选择的用途进入正确目录。
- 网页无法列出或访问机器包根目录及内部文件。
- 导出包含 ISO 时，ISO 位于导出包的 `Media/`，配置路径正确。
- 不包含介质的导出包不产生空 `Media/`。
- 桌面端外部资源仍可正常选择和启动。
